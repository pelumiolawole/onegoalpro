params, but the PostgreSQL :: cast operator after a named param
confuses the parser with "syntax error at or near ':'".

Using CAST(:key_shifts AS text[]) avoids the ambiguity.

2026-04-06 | 0fd5718 | Pelumi Olawole | fix: resolve asyncpg connection pool leak in coach streaming endpoint
The db session injected by FastAPI's Depends(get_db) was being passed
into stream_response(), an async generator that outlives the request.
FastAPI closed the connection before the stream finished, causing the
garbage collector to terminate it mid-session.

Fix: stream_response() no longer accepts db as a parameter. It opens
its own get_db_context() blocks at four points — context loading,
pre-stream saves, post-stream saves, and embeddings — so connections
are returned to the pool correctly after each operation.

Also fix: build_behavioral_snapshot() PostgreSQL function created.
Scheduler was calling a function that never existed in the database.
Added CAST(:user_id AS uuid) in run_behavioral_snapshots() to match
the function signature.
